# rs-spi 0.5 Clean-Break Design

**Status:** Accepted by the user on 2026-07-15
**Date:** 2026-07-15
**Scope:** `qubit-spi` and its direct workspace consumers: `qubit-fs`,
`qubit-mime`, and `qubit-magika`

## Context

`qubit-spi` 0.4 established the intended runtime model: explicit startup
registration, an immutable typed registry, deterministic automatic selection,
and synchronous service creation. A second review against the direct `rs-*`
consumers found that this architecture still matches the real requirements.

The remaining work is contract hardening and internal simplification rather
than another runtime redesign:

- public constructors can fabricate resolver-owned results and errors;
- aggregate attempts copy a `ProviderError` instead of owning it;
- the builder maintains one selector map during registration and rebuilds a
  second selector map during `build()`;
- source layout, Rustdoc, method order, inline attributes, and external test
  discovery do not satisfy the current repository rules;
- `qubit-mime` misclassifies a single unknown detector in a configured chain
  as a backend failure.

The user explicitly permits breaking changes and requested the cleanest
implementation without compatibility shims.

## Goals

- Make resolver and registry provenance impossible to fabricate through the
  public API.
- Preserve the original `ProviderError` inside aggregate attempt diagnostics.
- Build the selector index exactly once.
- Put every Rust type in its own source file and private representation types
  below `src/internal/`.
- Preserve useful root-level public type paths through re-exports.
- Complete Rustdoc, method ordering, inline classification, and external test
  organization according to current repository rules.
- Add precise boundary and regression tests, including the downstream MIME
  error-classification bug.
- Publish the breaking contract as `qubit-spi` 0.5 and update all direct
  workspace consumers.

## Non-goals

- Async provider construction.
- Runtime provider discovery, replacement, unloading, or global registries.
- A generic dependency-injection container or capability schema.
- A macro or generic wrapper for downstream domain registries.
- New fallback policies or a broader `ResolutionErrorKind` taxonomy.
- Compatibility aliases or deprecated forwarding constructors for 0.4.

## Considered Approaches

### Minimal API patch

Only restrict constructors, consume `ProviderError`, fix MIME mapping, and
leave the current file layout intact. This has the smallest diff but leaves
the current mandatory Rust organization and documentation debt unresolved.

### Strict clean break

Apply the API fixes and reorganize every type into its owning file, with
private representation types in `src/internal/`. Keep public types re-exported
from the crate root, but intentionally remove unsupported public construction
paths. This is the selected approach because compatibility is explicitly not
required and it leaves one coherent convention instead of a partial migration.

### Generalized resolver diagnostics

Add new public aggregate predicates or split `NoProviderSucceeded` into
multiple top-level kinds. The known data does not justify this extra API:
attempt kinds already describe the failures, and the concrete bug is a
downstream mapper ignoring them. This approach is rejected for now.

## Public Contract

The following root-level public types remain available:

- service contracts: `ServiceSpec`, `ServiceProvider`, `CreatedService`;
- identity and metadata: `ProviderId`, `ProviderSelector`,
  `ProviderDescriptor`;
- registry and resolution: `ProviderRegistry`, `ProviderRegistryBuilder`,
  `ResolvedProvider`, `ProviderResolver`, `ProviderSelection`,
  `FallbackPolicy`;
- public diagnostic values and their kind enums.

The following constructors become crate-private because only registry or
resolver execution can truthfully create them:

```rust
CreatedService::new(provider_id, service)
RegistrationError::duplicate_selector(...)
AttemptFailure::unknown_provider(selector)
AttemptFailure::provider_error(requested_selector, provider_id, error)
ResolutionError::unknown_provider(selector)
ResolutionError::invalid_selector(...)
ResolutionError::no_provider_succeeded(attempts)
```

`ResolutionError::unknown_provider` accepts an already parsed
`ProviderSelector`; it can no longer return a different error kind after
reparsing arbitrary text. `no_provider_succeeded` is called only with a
non-empty resolver-produced attempt list.

## Error Ownership

`AttemptFailureRepr::ProviderError` owns the original `ProviderError`:

```rust
enum AttemptFailureRepr {
    UnknownProvider {
        requested_selector: ProviderSelector,
        reason: Box<str>,
    },
    ProviderError {
        requested_selector: Option<ProviderSelector>,
        provider_id: ProviderId,
        error: ProviderError,
    },
}
```

The existing public accessors delegate to that error. This removes the copied
reason allocation and source `Arc` clone, while preserving the observable kind,
reason, and source chain.

## Registry Construction

`ProviderRegistryBuilder` stores `selector_indices: HashMap<ProviderSelector,
usize>` from the moment a registration succeeds. The pending registration
index is `registrations.len()`.

Conflict reporting resolves the existing provider through that index. The
final `build()` operation moves the map directly into `RegistryInner`; it only
converts registrations to immutable entries and computes automatic ordering.
It does not parse identifiers or clone selectors again.

## Source Organization

Every public struct, enum, and trait has one snake-case source file. In
particular, kind enums and formerly co-located public types move into files
such as:

- `attempt_failure.rs` and `attempt_failure_kind.rs`;
- `fallback_policy.rs`, `provider_selection.rs`, and
  `provider_selection_kind.rs`;
- `provider_error.rs` and `provider_error_kind.rs`;
- `resolved_provider.rs`;
- one `*_error_kind.rs` file for each public error kind.

Private builder entries, registry storage, selection representations, and
error representations live one type per file under `src/internal/`. `lib.rs`
contains module declarations, root re-exports, crate documentation, and the
canonical license header.

## Downstream Error Mapping

`qubit-mime` must inspect `AttemptFailureKind` before
`ProviderErrorKind`. A single `UnknownProvider` attempt maps to
`MimeError::UnknownDetector` using `requested_selector()`. Provider attempts
continue to map unavailable/unsupported failures to `DetectorUnavailable` and
other provider errors to `DetectorBackend`. Multiple exhausted attempts remain
`NoAvailableDetector`.

## Tests

- Add a failing MIME regression test before changing the mapper.
- Preserve all existing rs-spi behavior tests while reorganizing production
  types.
- Add table-driven `ProviderId` grammar boundaries.
- Add direct `ProviderRegistry::find` coverage.
- Move attempt-specific tests to `attempt_failure_tests.rs`.
- Enable one explicit integration-test harness with `autotests = false`,
  `[[test]] path = "tests/mod.rs"`, and module declarations in `tests/mod.rs`.
- Rename tests to `test_<subject>_<scenario>` and document tests and fixtures.

## Documentation and Style

Every Rust file receives the repository copyright header. Every type, field,
variant field, function, method, fixture, and test helper receives accurate
Rustdoc. Applicable `# Arguments`, `# Returns`, `# Errors`, and `# Panics`
sections are added. Getter, setter, and pure forwarding bodies use
`#[inline(always)]`; other short bodies use `#[inline]`; branch-heavy and
iterative bodies remain uninlined. Inherent methods are ordered by constructor
status, visibility, then functional adjacency.

## Versioning and Packaging

`qubit-spi` becomes version `0.5.0`. Direct workspace dependencies use version
`0.5`. README dependency examples are updated in both languages. The package
include list is reduced to files that actually exist and belong in the crate
package; internal design and plan documents are not published.
