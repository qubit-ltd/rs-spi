# rs-spi 0.8 API Hardening Design

**Status:** Approved in conversation on 2026-07-16
**Scope:** `qubit-spi` and its direct workspace consumers `qubit-fs`,
`qubit-mime`, and `qubit-magika`

## Goal

Finish the current API simplification with one intentional 0.8 breaking
release: make selector-validation errors own one canonical copy of their
context, keep error enums directly matchable while reserving their
construction to `qubit-spi`, align standard error chaining with resolution
semantics, clarify string ownership at public boundaries, and remove
migration-only material from published documentation.

Selector lookup allocation optimization and output-only resolver APIs remain
outside this change because the workspace provides no benchmark evidence that
their added complexity is justified.

## Considered Approaches

### Minimal behavioral patch

Only change `ResolutionError::source()` and clean the documentation. This has
the smallest diff, but preserves duplicated selector input, the artificial
named-selection index, externally constructible invariant-bearing errors, and
the special-case translation in `ProviderResolver::create_named`.

### Invariant-owned directly matchable errors

Keep the public error enums and their fields available for pattern matching,
but make struct-like variants non-exhaustive so only `qubit-spi` can construct
them. Store raw selector input only in `ProviderSelectorError`, use an optional
index to distinguish direct input from chain input, and move the parse source
between error layers without copying its text. This preserves the direct
matching model while removing correlated duplicate state.

This is the selected approach.

### Fully opaque errors with borrowed views

Make errors opaque and expose borrowed view enums or accessor methods. This
would enforce construction invariants, but recreates the parallel inspection
API that 0.7 deliberately removed. It is rejected as unnecessary abstraction.

## Versioning

`qubit-spi` changes from 0.7.0 to 0.8.0 because the public function signatures
and error-variant fields change incompatibly. The three direct workspace
consumers update their path dependency requirement from `0.7` to `0.8` and
receive independent commits in their own repositories.

## Selector Error Model

`ProviderSelectorError` remains the sole owner of verbatim selector input. Its
existing `input()` method continues to return that input for every variant.

`ProviderSelectionError::InvalidSelector` becomes:

```rust
#[non_exhaustive]
InvalidSelector {
    selector_index: Option<usize>,
    #[source]
    source: ProviderSelectorError,
}
```

`ProviderSelection::named` records `None`; `ProviderSelection::chain` records
`Some(index)`. Display text omits an index for named input and includes the
zero-based selection index for chain input.

`ResolutionError::InvalidSelector` uses the same two fields and the same index
semantics. `From<ProviderSelectionError>` moves both fields directly, without
reallocating input text. `ProviderResolver::create_named` parses a
`ProviderSelector` directly and delegates to `create_named_selector`, removing
the temporary `ProviderSelection` and the impossible `EmptyChain` branch.

`ProviderDescriptorError::InvalidAlias` retains `alias_index` and `source`, but
removes its duplicate `alias` field. `ProviderDescriptorError::alias()` returns
`source.input()` for invalid aliases and the stored normalized alias for the
two conflict variants.

No replacement optional accessors or parallel Kind types are introduced.
Downstream callers continue matching enum variants directly and use
`source.input()` when they need rejected input.

## Construction Boundaries

Every public struct-like variant in these error enums becomes individually
`#[non_exhaustive]`:

- `ProviderIdError`;
- `ProviderSelectorError`;
- `ProviderDescriptorError`;
- `ProviderSelectionError`;
- `RegistrationError`;
- `AttemptFailure`;
- `ResolutionError`.

Enum-level `#[non_exhaustive]` remains to reserve future variants. Variant-level
`#[non_exhaustive]` reserves construction to `qubit-spi` and requires
downstream patterns to include `..`. This protects, in particular, the
non-empty `ResolutionError::NoProviderSucceeded` attempt invariant without
making errors opaque.

Unit variants remain constructible because they contain no correlated fields
or private invariants.

## Standard Error Chaining

`ResolutionError::decisive_attempt()` remains the authoritative definition of
an unambiguous aggregate cause:

- the terminal attempt for `StoppedByPolicy`;
- the sole attempt for singleton `Exhausted`;
- no attempt for multi-attempt `Exhausted`.

`Error::source()` returns that decisive attempt for aggregate errors. A
multi-attempt resolution that stops by policy therefore exposes the terminal
provider failure through the standard chain, while an ambiguous exhausted
aggregate still has no single source. Invalid selector errors continue to
expose their `ProviderSelectorError` source.

## String Boundaries and Ownership

Public operations that only borrow one string accept `&str` rather than
`impl AsRef<str>`:

- `ProviderId::new`;
- `ProviderSelector::parse`;
- `ProviderSelection::named`;
- `ProviderResolver::create_named`;
- `ProviderRegistry::resolve`;
- `ProviderRegistry::find`.

Iterator-based alias and chain APIs retain `T: AsRef<str>` because they accept
both borrowed and owned iterator items without taking ownership of the
collection.

`ProviderError` constructors must own their reason, so their reason parameter
changes from `impl AsRef<str>` to `impl Into<Box<str>>`. Passing a `Box<str>` or
`String` can then transfer its allocation instead of forcing another copy,
while string literals remain accepted.

## Documentation

The public `qubit_spi::error` module removes the five migration-only
`compile_fail` examples naming deleted Kind types. It gains:

- a positive example of direct non-exhaustive error matching;
- one current-contract `compile_fail` example showing that an
  invariant-bearing error variant cannot be constructed downstream.

The public performance sections on `ProviderSelector::parse` and
`ProviderResolver::create_named` describe current behavior: each raw call owns
a normalized selector, and callers with reusable configuration should cache a
`ProviderSelection`. Developer-facing benchmark TODO text is removed from
published Rustdoc.

The English and Chinese READMEs update to 0.8 and state that standard error
chaining exposes a decisive attempt, not only a singleton aggregate.

Historical design and implementation documents remain unchanged because they
record the decisions made for their respective releases rather than current
public API guidance.

## Inline Alignment

The repository inline matrix is applied to the confirmed mismatches:

- `ProviderRegistry::from_inner` becomes `#[inline(always)]` as a one-field
  wrapper;
- `ResolutionError::source`, `AttemptFailure::source`, and
  `ProviderResolver::should_continue` become `#[inline]` because they branch.

No unrelated formatting or inline churn is included.

## Downstream Migration

### qubit-mime

MIME selection adapters read rejected names from
`ProviderSelectorError::input()`. Resolution adapters use the selector source
for both classification and input text. All struct-variant patterns include
`..`. The detector and classifier continue to use `decisive_attempt()` for
domain-specific mapping.

### qubit-fs

Filesystem production behavior remains unchanged. The dependency requirement
and user-guide installation/version references move to 0.8. Existing
`ResolutionError::is_absence()` mapping remains valid.

### qubit-magika

The dependency requirement moves to 0.8. Its owned initialization-failure
message transfers into `ProviderError` through `Into<Box<str>>`; provider
selection behavior does not change.

## Test-First Implementation

Implementation follows independent red-green cycles:

1. Add a resolver regression test in which one fallback-eligible failure is
   followed by a policy-stopping failure; require `Error::source()` to expose
   the terminal `AttemptFailure`.
2. Change named and chained selection tests to require `None` and `Some(index)`
   respectively, then implement the optional index and source-only error
   representation.
3. Add a current-contract compile-fail doctest for external construction of
   `NoProviderSucceeded`, then add variant-level non-exhaustive attributes.
4. Add a `ProviderError` test proving an owned `Box<str>` reason allocation is
   transferred, then change reason constructors to `Into<Box<str>>`.
5. Migrate downstream matches only after their compilation fails against the
   new 0.8 API.
6. Update public documentation, version requirements, and inline attributes,
   then run the complete prescribed verification sequence.

Tests continue to cover invalid named input, invalid chain positions, invalid
aliases, direct unknown providers, singleton and aggregate failure sources,
policy termination, absence classification, and every existing public error
variant.
