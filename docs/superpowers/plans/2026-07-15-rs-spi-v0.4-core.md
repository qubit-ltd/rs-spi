# rs-spi 0.4 Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the mutable, multi-handle SPI registry with an immutable provider catalog, policy-driven resolver, classified creation errors, and an output-owned service specification.

**Architecture:** `ProviderRegistryBuilder<S>` validates explicit registrations and freezes them into an `Arc`-backed `ProviderRegistry<S>`. `ProviderResolver<S>` expands a selection, applies a fallback policy, and returns `CreatedService<S::Output>`. Providers only create services; metadata belongs to registrations.

**Tech Stack:** Rust 2024, Rust 1.94, `std::{collections::HashMap, sync::Arc}`, and `thiserror` 2.0. Remove `log`.

## Global Constraints

- Work in the current `rs-spi` checkout on `dev-starfish`; the user explicitly declined a separate worktree.
- Release a breaking `0.4.0`; do not provide deprecated compatibility shims.
- Keep registration explicit and startup-only; do not add discovery, async, global mutable state, or DI features.
- `ServiceSpec` owns one complete, sized `Output`; core code never converts among `Box`, `Arc`, and `Rc`.
- Use TDD: write one focused integration test, observe its expected failure, implement only enough code, then rerun it.
- Do not edit dirty downstream worktrees in this core plan. Their migration is documented in `docs/superpowers/specs/2026-07-15-rs-spi-v0.4-design.md`.

```rust
#[derive(Clone, Debug, Eq, PartialEq)]
pub enum ProviderSelection {
    Auto,
    Named(ProviderSelector),
    Chain(Box<[ProviderSelector]>),
}

#[derive(Clone, Copy, Debug, Default, Eq, PartialEq)]
pub enum FallbackPolicy {
    #[default]
    OnAbsence,
    OnAnyError,
}

pub struct ProviderResolver<S: ServiceSpec> {
    registry: ProviderRegistry<S>,
    fallback_policy: FallbackPolicy,
}

impl<S: ServiceSpec> ProviderResolver<S> {
    pub fn new(registry: ProviderRegistry<S>, fallback_policy: FallbackPolicy) -> Self;
    pub fn create(&self, selection: &ProviderSelection, config: &S::Config)
        -> Result<CreatedService<S::Output>, ResolutionError>;
}
```

For `OnAbsence`, continue after unknown selectors, `Unsupported`, and `Unavailable`; stop after `InvalidConfiguration` and `InitializationFailed`. `OnAnyError` continues after every attempt failure. De-duplicate aliases that resolve to one provider. Do not emit logs.
